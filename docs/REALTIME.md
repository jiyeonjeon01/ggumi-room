# 실시간 기능 (WebSocket)

탭마다 WebSocket 하나(`/ws/live`)를 열고, 방 동기화·친구 접속 상태·1:1 채팅이 이 연결을 같이 씁니다.

```
브라우저 ──wss://www.ggumiroom.com/ws/live──▶ Cloudflare ─▶ Tunnel ─▶ nginx(/ws/ 업그레이드) ─▶ FastAPI(api:8000)
```

| 파일 | 역할 |
|---|---|
| `api/app/realtime/ws.py` | 엔드포인트: 핸드셰이크 검사, 프레임 읽기·쓰기, 메시지 분기 |
| `api/app/realtime/hub.py` | 연결·방 상태(`Hub`), 이동 검증, 방송, 속도 제한 |
| `api/app/realtime/geometry.py` | 서버용 충돌 판정 (`src/game/core/collision.ts`와 같은 규칙, 같은 카탈로그) |
| `src/net/live.ts` | 클라이언트 연결: 재연결(1→2→4→…15초, 지터), 20초 ping, 4401/4403이면 중단 |
| `src/app/live.tsx` | 로그인한 동안 탭당 연결 1개 (`LiveProvider`) |
| `src/app/roomLive.ts` | 방 입장·이벤트를 게임에 반영 (`useRoomLive`) |
| `src/game/net/motion.ts` | 이동 보고 제한(`MoveReporter`), 다른 사람 보간(`RemoteMotion`) |

## 연결과 인증

- **Origin**: 핸드셰이크의 `Origin`이 `PUBLIC_BASE_URL`(+`EXTRA_ALLOWED_ORIGINS`)이 아니면 업그레이드를 거절합니다 (HTTP 403).
- **세션**: 기존 HttpOnly 쿠키 `ggumi_session`. 없거나 만료면 연결을 받은 뒤 `4401`로 닫습니다(클라이언트가 재시도하지 않게).
- **신원**: 사용자 ID·닉네임은 세션에서만 정합니다. 클라이언트가 보낸 `user_id`, `nickname` 같은 값은 무시합니다. 방 안의 각 사람은 서버가 만든 연결 ID(`id`)로 구분합니다.
- **로그아웃**: `POST /api/auth/logout`이 그 세션으로 열린 모든 소켓을 바로 닫습니다(`4401`). 세션이 DB에서 사라지거나 만료되면 다음 ping(최대 60초마다 재확인) 때 닫습니다.
- **하트비트**: 클라이언트가 20초마다 `ping`, 서버가 `pong`. 45초 동안 아무 프레임이 없으면 서버가 닫습니다(`4408`). uvicorn의 프로토콜 ping(20초)도 끊긴 TCP를 잡습니다. Cloudflare 유휴 제한(100초)보다 짧습니다.

### 접근 권한

`join`마다 HTTP API와 같은 `room_access` 규칙(주인 / 친구 / 초대 수락한 손님)을 DB에서 다시 확인합니다. 친구를 끊으면 초대로 들어온 기록이 없는 쪽은 상대 방에서 바로 빠집니다(`room.denied`). 가구 편집은 기존대로 HTTP `PUT /api/rooms/{id}/items`에서 주인만 가능하고, WebSocket에는 편집 메시지가 없습니다.

### 이동 검증

서버는 방마다 가구 배치로 충돌 정보를 만들고, `move`마다 다음을 확인합니다.

1. 숫자 값(무한대·NaN 불가), 방향·상태 값이 정해진 것인지
2. 새 위치가 방 안이고 막는 가구와 겹치지 않는지 (반지름 0.22의 90%)
3. 이전 위치에서 새 위치까지 직선 경로가 가구·벽을 지나지 않는지 (반지름의 60%, 모서리 미끄러짐 허용)
4. 거리 ≤ 걷기 속도(2.6칸/초) × 경과 시간 × 1.35 + 0.35칸 (타이머 오차와 묶여 도착하는 메시지 여유)

어긋나면 다른 사람에게 보내지 않고 보낸 사람에게 `move.fix`를 보냅니다. 주인이 배치를 저장하면 서버가 충돌 정보를 바꾸고, 가구 안에 있게 된 사람은 가장 가까운 빈칸으로 옮기며, 다음 위치 하나는 속도 검사 없이 받습니다(클라이언트도 방을 다시 그리며 캐릭터를 빈칸으로 옮기기 때문).

### 보간

받은 이동을 도착 시각과 함께 쌓고, 다른 사람은 **120ms 전 시점**으로 그립니다. 그 시점을 둘러싼 두 업데이트 사이를 선형 보간하므로 업데이트가 고르지 않게 와도 끊기지 않습니다. 최신 업데이트를 지나면 그 자리에 멈추고(예측해서 지나치지 않음), 2.5칸 넘게 차이 나면 미끄러지지 않고 바로 옮깁니다.

### 여러 탭·기기

- 탭마다 연결이 따로 있습니다 (접속 상태·메시지는 모든 탭에 전달).
- **한 방 안에서 한 사람의 캐릭터는 하나**입니다. 같은 방에 다른 탭·기기로 들어오면 먼저 있던 쪽은 `room.replaced`를 받고 방에서 빠지며, 화면에 "다른 탭이나 기기에서 이 방에 들어가서, 여기서는 혼자 보고 있어요. [여기서 함께하기]"가 보입니다. 버튼을 누르면 반대로 넘어옵니다.
- 서로 다른 방은 탭마다 동시에 들어갈 수 있습니다.

### 끊김·재연결·서버 재시작

- 연결이 끊기면 다른 사람 캐릭터를 바로 지우고 "실시간 연결 중이에요" 안내를 보입니다(남아 있는 척하지 않음).
- 재연결되면 마지막 위치로 다시 `join`합니다. 서버 재시작 시 방 상태는 메모리에만 있으므로 클라이언트들이 다시 들어오며 복원됩니다(측정: 약 2.4초).
- 브라우저의 `online` 이벤트가 오면 백오프를 기다리지 않고 바로 다시 연결합니다.

## 친구 접속 상태 (Phase 2)

친구 목록(`FriendsPanel`)의 이니셜 동그라미에 점이 붙고, 이름 아래에 상태 글자가 보입니다. 온라인 → 자리비움 → 오프라인 순으로 정렬합니다.

| 표시 | 상태 | 기준 (사용자 단위, 모든 탭·기기 합산) |
|---|---|---|
| 초록 ● 온라인 | `online` | 연결이 하나 이상 있고, 어느 탭에서든 최근 5분 안에 실제 입력이 있음 |
| 노랑 ● 자리비움 | `away` | 연결은 있지만 5분 넘게 실제 입력이 없음 (다른 탭·창에 가서 아무것도 안 해도 포함) |
| 회색 ● 오프라인 | `offline` | 연결이 하나도 없음 (로그아웃·브라우저 종료·네트워크 끊김) |
| 빈 원 ○ 상태 확인 중 | (모름) | 내 실시간 연결이 없을 때. 모르는 상태를 온라인으로 보이지 않게 함 |

### 무엇이 "실제 활동"인가

- 그 탭의 `pointerdown`, `pointermove`, `keydown`, `wheel`, `touchstart`, 창 `focus`, 탭이 다시 보이게 됨(`visibilitychange` → visible)
- 방 안에서 이동(`move`)하거나 말풍선(`say`)을 보냄 (서버가 직접 셈)
- **활동이 아닌 것**: `ping` 하트비트, 연결만 유지되는 상태, 숨은 탭

클라이언트는 입력이 있을 때 `activity`를 **최대 30초에 한 번** 보냅니다(자리비움 기준의 1/4보다 자주 보내지 않음). 그래서 마우스를 계속 움직여도 30초에 한 건입니다. 연결(재연결)하면 `welcome` 직후 `activity {idle_ms}`로 마지막 입력이 얼마나 지났는지 알려서, 오래 쉬던 백그라운드 탭이 재연결하자마자 온라인이 되지 않게 합니다.

### 판정 시점

- **로그인·접속 직후**: 바로 온라인으로 반영 (`welcome`에 친구 상태 목록 포함)
- **자리비움**: 서버가 15초마다(기준이 짧으면 기준의 1/5마다) 다시 계산
- **로그아웃**: 즉시 오프라인
- **탭 닫기·새로고침·네트워크 끊김**: 마지막 연결이 끊긴 뒤 **10초 유예**. 그 안에 다시 연결되면(새로고침) 오프라인을 보내지 않음. 신호 없이 끊긴 네트워크는 하트비트 시간 초과(45초) 뒤 끊김으로 처리
- 상태가 실제로 바뀔 때만 보냄(같은 상태 반복 없음)

### 설정

API 환경 변수 `PRESENCE_AWAY_S`(자리비움 기준, 기본 300초), `PRESENCE_GRACE_S`(끊김 유예, 기본 10초). 로컬 E2E에서만 짧게 바꾸고, 운영 `docker-compose.yml`에는 넘기지 않아 기본값을 씁니다.

## 친구 1:1 채팅 (Phase 3)

친구 목록의 💬 버튼으로 엽니다. 방 안에서 Enter로 쓰는 말풍선(같은 방에만, 저장 안 함)과는 별개 기능입니다.

### DB (`ca9664530522`, 새 테이블만 추가)

| 테이블 | 열 | 설명 |
|---|---|---|
| `conversations` | `id`, `user_a_id` < `user_b_id`(고유 쌍), `last_message_at`, `a_read_seq`, `b_read_seq` | 친구 쌍마다 하나. 각자 "상대 메시지를 어디까지 읽었는지"를 seq로 저장 |
| `messages` | `id`, `seq`(전체 증가 번호), `conversation_id`, `sender_id`, `body`(1~500자, DB 제약), `client_id`, `created_at` | `(sender_id, client_id)` 고유 → 같은 전송을 다시 보내도 한 번만 저장. `(conversation_id, seq)` 인덱스로 페이지 |

내려도(downgrade) 이 두 테이블만 지워집니다. 기존 계정·친구·방 데이터는 건드리지 않습니다.

### HTTP API (세션 + CSRF, 친구끼리만)

| 메서드·경로 | 설명 |
|---|---|
| `GET /api/messages/conversations` | 내 대화 목록(최신 메시지 순): 친구, 마지막 메시지, 읽지 않은 수, 상대가 읽은 위치 |
| `GET /api/messages/with/{friend_id}?before=&limit=` | 대화 기록(오래된 순), `before`(seq)부터 거꾸로 30개씩, `has_more` |
| `POST /api/messages/with/{friend_id}` | `{body, client_id}` 보내기. 같은 `client_id`면 처음 저장된 것을 돌려줌 |
| `POST /api/messages/with/{friend_id}/read` | `{up_to_seq}` 여기까지 읽음. 뒤로 가지 않고, 마지막 메시지를 넘지 않음 |

- 친구가 아니면(또는 친구를 끊으면) 보내기·기록·읽음 모두 404, 대화 목록에서도 빠집니다.
- 본문: 제어 문자 제거(줄바꿈은 유지), 빈 줄 3개 이상은 2개로, 앞뒤 공백 제거, **500자·30줄 초과는 422**(자르지 않음). HTML은 그대로 글자로 저장하고 화면도 글자로만 그립니다(`whitespace-pre-wrap`, React 이스케이프) → 스크립트가 실행되지 않음.
- 제한: 보내기 10초에 10개·시간당 300개, 읽음 분당 120회.
- 메시지 본문은 어떤 로그에도 남기지 않습니다 (uvicorn 접근 로그 꺼짐, nginx 로그는 경로만, 경로에는 친구 ID만).

### 실시간 이벤트

| 방향 | `t` | 필드 | 설명 |
|---|---|---|---|
| 서버→ | `dm.new` | `message` | 저장된 메시지. 받는 사람의 모든 탭 + 보낸 사람의 모든 탭(보낸 탭은 `client_id`로 중복 제거) |
| 서버→ | `dm.read` | `reader`, `peer`, `seq` | `reader`가 `peer`의 메시지를 `seq`까지 읽음 → 보낸 쪽 진한 체크, 읽은 쪽 다른 기기의 배지 정리 |
| →서버 | `dm.typing` | `to`, `on` | 입력 중 켜짐/꺼짐. 서버가 친구인지 확인한 뒤 그 친구에게만 전달, **저장하지 않고 본문을 담지 않음**(보내도 버림), 연결당 10초에 20개 |
| 서버→ | `dm.typing` | `from`, `on` | |

### 화면

- **전송 상태**: 보내는 중 → 작은 회전 표시 / 저장됨·상대 미확인 → 아주 연한 분홍 ✓ / 상대 확인 → 진한 분홍 ✓ / 실패 → "다시 보내기"(같은 `client_id`로 재전송)
- **읽음 처리 조건** (모두 만족할 때만 읽음 요청): 대화창이 열려 있고 최소화되지 않음, 탭이 보이고(`visibilityState`) 창에 포커스가 있음(`document.hasFocus()`), 맨 아래 메시지가 보이는 위치까지 스크롤됨. 다른 탭에 가 있거나 위쪽 기록을 보는 중이면 읽음으로 바꾸지 않습니다.
- **입력 중**: "꾸미님이 입력 중" + 점 3개가 차례로 오르내리는 애니메이션. 입력이 있으면 최대 3초에 한 번 켜짐을 보내고, 5초 동안 입력이 없거나 보내기·창 닫기·최소화하면 꺼짐. 받는 쪽은 6초 동안 소식이 없으면 스스로 숨김.
- **배지**: 친구 행의 💬 위에 그 친구의 읽지 않은 수, 친구 패널 제목·태블릿 레일·모바일 탭에 전체 수. 창이 닫혀 있거나 최소화돼 있으면 "💬 OO님의 새 메시지가 왔어요." 토스트.
- **배치**: 데스크톱은 오른쪽 아래 320×440 창(친구 패널 위, 게임 화면은 가리지 않음), 모바일은 화면 아래쪽 시트(위 30%는 게임이 보임). 최소화하면 이름과 읽지 않은 수만 있는 알약 버튼.
- Enter 보내기, Shift+Enter 줄바꿈, 한글 조합 중 Enter는 보내지 않음, Esc 최소화. 채팅창은 모달이 아니라서 꾸미기 단축키를 막지 않습니다.
- 재연결하면 대화 목록(읽지 않은 수)과 열린 대화를 다시 불러와 끊긴 동안의 메시지를 채웁니다.

## 여러 서버로 늘릴 때

지금은 API 프로세스 하나(uvicorn worker 1)에서 `Hub`가 메모리로 연결·방·접속 상태를 관리합니다. 접속 상태는 사용자별 연결 목록에서 계산하므로, 여러 서버에서는 연결 목록(사용자 → 서버·마지막 활동 시각)을 브로커에 두어야 합니다. 서버를 늘릴 때는 `Hub`의 공개 메서드(`join_room`, `move`, `say`, `layout_changed`, `close_sessions` …)를 그대로 두고, 방·사용자 단위 방송을 Redis pub/sub 같은 브로커로 바꾸면 됩니다. 라우터와 WebSocket 엔드포인트는 `Hub`만 호출합니다. 로드밸런서는 WebSocket 업그레이드를 지원해야 하고, 고정 세션(sticky)은 필요 없습니다(상태는 브로커에).
