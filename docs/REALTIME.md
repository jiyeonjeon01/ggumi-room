# 실시간 기능 (WebSocket)

탭마다 WebSocket 하나(`/ws/live`)를 열고, 방 동기화·친구 접속 상태·1:1 채팅이 이 연결을 같이 씁니다.

```
브라우저 ──wss://www.ggumiroom.com/ws/live──▶ Cloudflare ─▶ Tunnel ─▶ nginx(/ws/ 업그레이드) ─▶ FastAPI(api:8000)
```

| 파일 | 역할 |
|---|---|
| `api/app/realtime/ws.py` | 엔드포인트: 핸드셰이크 검사, 프레임 읽기·쓰기, 메시지 분기 |
| `api/app/realtime/hub.py` | 연결·방 상태(`Hub`), 이동 검증, 방송, 속도 제한 |
| `api/app/realtime/geometry.py` | 서버용 충돌 판정 (`src/game/core/collision.ts`와 같은 규칙, 같은 카탈로그) |
| `src/net/live.ts` | 클라이언트 연결: 재연결(1→2→4→…15초, 지터), 20초 ping, 4401/4403이면 중단 |
| `src/app/live.tsx` | 로그인한 동안 탭당 연결 1개 (`LiveProvider`) |
| `src/app/roomLive.ts` | 방 입장·이벤트를 게임에 반영 (`useRoomLive`) |
| `src/game/net/motion.ts` | 이동 보고 제한(`MoveReporter`), 다른 사람 보간(`RemoteMotion`) |

## 연결과 인증

- **Origin**: 핸드셰이크의 `Origin`이 `PUBLIC_BASE_URL`(+`EXTRA_ALLOWED_ORIGINS`)이 아니면 업그레이드를 거절합니다 (HTTP 403).
- **세션**: 기존 HttpOnly 쿠키 `ggumi_session`. 없거나 만료면 연결을 받은 뒤 `4401`로 닫습니다(클라이언트가 재시도하지 않게).
- **신원**: 사용자 ID·닉네임은 세션에서만 정합니다. 클라이언트가 보낸 `user_id`, `nickname` 같은 값은 무시합니다. 방 안의 각 사람은 서버가 만든 연결 ID(`id`)로 구분합니다.
- **로그아웃**: `POST /api/auth/logout`이 그 세션으로 열린 모든 소켓을 바로 닫습니다(`4401`). 세션이 DB에서 사라지거나 만료되면 다음 ping(최대 60초마다 재확인) 때 닫습니다.
- **하트비트**: 클라이언트가 20초마다 `ping`, 서버가 `pong`. 60초 동안 아무 프레임이 없으면 서버가 닫습니다(`4408`). uvicorn의 프로토콜 ping(20초)도 끊긴 TCP를 잡습니다. Cloudflare 유휴 제한(100초)보다 짧습니다.

### 닫힘 코드

| 코드 | 뜻 | 클라이언트 |
|---|---|---|
| 1000 | 정상 종료 | 재연결 |
| 1009 | 프레임이 4KB 초과 | 재연결 |
| 4400 | 프로토콜 위반(바이너리, JSON 오류 5회) | 재연결 |
| 4401 | 로그인 안 됨·로그아웃·세션 만료 | **중단**, "다시 로그인" 안내 |
| 4403 | Origin 불일치 (핸드셰이크 거절) | **중단** |
| 4408 | 하트비트 없음 / 너무 느려서 전송 큐가 참 | 재연결 |
| 4429 | 연결 수·메시지 수 초과 | 재연결(백오프) |

## 제한

| 항목 | 한도 |
|---|---|
| 새 연결 | IP당 분당 30회 |
| 동시 연결 | 사용자당 8개 (탭·기기 합계) |
| 프레임 크기 | 4KB (uvicorn `--ws-max-size 16384`도 함께) |
| 전체 메시지 | 연결당 초당 60개 (넘으면 버림, 계속 넘으면 `4429`) |
| 이동 | 연결당 초당 15개 (클라이언트는 걷는 동안 약 10개, 서 있으면 0개) |
| 말풍선 | 0.5초에 1개, 10초에 6개 (넘으면 `error: chat_rate`) |
| 방 입장 | 10초에 10회 |
| 전송 큐 | 연결당 256개 (못 따라오는 클라이언트는 `4408`로 끊어 다른 사람에게 영향 없음) |

## 방 동기화 (Phase 1)

### 이벤트

클라이언트 → 서버

| `t` | 필드 | 설명 |
|---|---|---|
| `ping` | | 하트비트 |
| `join` | `room`, `x?`, `y?`, `f?` | 방 입장(이전 방에서는 나감). 위치는 제안일 뿐, 서버가 확인 |
| `leave` | | 방에서 나감 |
| `move` | `x`, `y`, `f`, `s` | 내 위치·방향(`front-right` 등 4가지)·상태(`idle`/`walk`) |
| `say` | `text` | 말풍선 (24자, 한 줄) |

서버 → 클라이언트

| `t` | 필드 | 설명 |
|---|---|---|
| `welcome` | `id`, `user_id`, `nickname` | 연결 확인 (이때부터 "연결됨") |
| `pong` | | |
| `room.state` | `room`, `you`, `members[]` | 입장 결과. `you`는 서버가 정한 내 위치 |
| `room.join` / `room.leave` | `member` / `id` | 다른 사람이 들어오거나 나감 |
| `move` | `id`, `x`, `y`, `f`, `s` | 다른 사람 이동 (보낸 사람에게는 안 감) |
| `move.fix` | `x`, `y` | 내 이동이 거절됨: 서버가 마지막으로 인정한 위치로 돌아감 |
| `say` | `id`, `text` | 다른 사람 말풍선 (보낸 사람은 이미 화면에 표시) |
| `room.layout` | `version`, `items` | 주인이 배치를 저장함 |
| `room.theme` | `theme` | 주인이 테마를 바꿈 |
| `room.replaced` | | 내 다른 탭·기기가 이 방에 들어와서 여기서는 빠짐 |
| `room.denied` | `code` | 들어갈 권한이 없음(또는 친구 해제로 잃음) |
| `error` | `code` | `chat_rate`, `not_in_room`, `rate` |

### 접근 권한

`join`마다 HTTP API와 같은 `room_access` 규칙(주인 / 친구 / 초대 수락한 손님)을 DB에서 다시 확인합니다. 친구를 끊으면 초대로 들어온 기록이 없는 쪽은 상대 방에서 바로 빠집니다(`room.denied`). 가구 편집은 기존대로 HTTP `PUT /api/rooms/{id}/items`에서 주인만 가능하고, WebSocket에는 편집 메시지가 없습니다.

### 이동 검증

서버는 방마다 가구 배치로 충돌 정보를 만들고, `move`마다 다음을 확인합니다.

1. 숫자 값(무한대·NaN 불가), 방향·상태 값이 정해진 것인지
2. 새 위치가 방 안이고 막는 가구와 겹치지 않는지 (반지름 0.22의 90%)
3. 이전 위치에서 새 위치까지 직선 경로가 가구·벽을 지나지 않는지 (반지름의 60%, 모서리 미끄러짐 허용)
4. 거리 ≤ 걷기 속도(2.6칸/초) × 경과 시간 × 1.35 + 0.35칸 (타이머 오차와 묶여 도착하는 메시지 여유)

어긋나면 다른 사람에게 보내지 않고 보낸 사람에게 `move.fix`를 보냅니다. 주인이 배치를 저장하면 서버가 충돌 정보를 바꾸고, 가구 안에 있게 된 사람은 가장 가까운 빈칸으로 옮기며, 다음 위치 하나는 속도 검사 없이 받습니다(클라이언트도 방을 다시 그리며 캐릭터를 빈칸으로 옮기기 때문).

### 보간

받은 이동을 도착 시각과 함께 쌓고, 다른 사람은 **120ms 전 시점**으로 그립니다. 그 시점을 둘러싼 두 업데이트 사이를 선형 보간하므로 업데이트가 고르지 않게 와도 끊기지 않습니다. 최신 업데이트를 지나면 그 자리에 멈추고(예측해서 지나치지 않음), 2.5칸 넘게 차이 나면 미끄러지지 않고 바로 옮깁니다.

### 여러 탭·기기

- 탭마다 연결이 따로 있습니다 (접속 상태·메시지는 모든 탭에 전달).
- **한 방 안에서 한 사람의 캐릭터는 하나**입니다. 같은 방에 다른 탭·기기로 들어오면 먼저 있던 쪽은 `room.replaced`를 받고 방에서 빠지며, 화면에 "다른 탭이나 기기에서 이 방에 들어가서, 여기서는 혼자 보고 있어요. [여기서 함께하기]"가 보입니다. 버튼을 누르면 반대로 넘어옵니다.
- 서로 다른 방은 탭마다 동시에 들어갈 수 있습니다.

### 끊김·재연결·서버 재시작

- 연결이 끊기면 다른 사람 캐릭터를 바로 지우고 "실시간 연결 중이에요" 안내를 보입니다(남아 있는 척하지 않음).
- 재연결되면 마지막 위치로 다시 `join`합니다. 서버 재시작 시 방 상태는 메모리에만 있으므로 클라이언트들이 다시 들어오며 복원됩니다(측정: 약 2.4초).
- 브라우저의 `online` 이벤트가 오면 백오프를 기다리지 않고 바로 다시 연결합니다.

## 여러 서버로 늘릴 때

지금은 API 프로세스 하나(uvicorn worker 1)에서 `Hub`가 메모리로 연결·방을 관리합니다. 서버를 늘릴 때는 `Hub`의 공개 메서드(`join_room`, `move`, `say`, `layout_changed`, `close_sessions` …)를 그대로 두고, 방·사용자 단위 방송을 Redis pub/sub 같은 브로커로 바꾸면 됩니다. 라우터와 WebSocket 엔드포인트는 `Hub`만 호출합니다. 로드밸런서는 WebSocket 업그레이드를 지원해야 하고, 고정 세션(sticky)은 필요 없습니다(상태는 브로커에).
