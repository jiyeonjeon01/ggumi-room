# 확장 설계 메모 (가구 디자인·닉네임 꾸미기·잠금 보상·테마·맵)

아직 구현하지 않은 기능을 나중에 붙일 때 지금 구조를 크게 바꾸지 않도록 정리한 메모입니다. 확정된 기획이 아니고, 현재 코드가 어디까지 받쳐 주는지와 붙일 자리를 적었습니다.

## 지금 구조 요약

| 영역 | 현재 | 위치 |

| 가구 카탈로그 | 15종. 크기(w·h), 막힘 여부, 회전 순서를 한 JSON에 두고 프론트·API가 같이 읽음 | `shared/furniture.json` `items` |

## 1. 가구별 2~3종 디자인 (변형)

- **데이터**: `room_items`에 `variant`(작은 정수, 기본 0) 열을 추가하는 마이그레이션 하나면 됩니다. 기존 행은 0이라 지금 모습 그대로입니다.
  - 카탈로그 `items.<id>.variants: [{ "name": "기본" }, { "name": "레트로", "unlock": "…" }]`처럼 같은 JSON에 두면 프론트·서버가 같은 목록으로 검사합니다(`api/app/layout.py`의 `validate`에 `bad_variant` 추가).
  - 크기·충돌이 다른 디자인은 변형이 아니라 **새 종류**로 두는 것이 안전합니다. 변형은 같은 자리·같은 충돌을 전제로 합니다(배치 검사·실시간 충돌 `realtime/geometry.py`를 건드리지 않음).
- **그림**: `ART[id]`를 `ART[id][variant]`로 넓히고, 텍스처 캐시 키(`textures.ts`)에 변형 번호를 넣습니다. 방향 4개 처리(축 교환·180°·깊이 그리기)는 그대로 재사용됩니다.
- **편집기**: `LayoutItem`에 `variant`를 더하고, 꾸미기 패널에서 같은 종류의 변형을 고르는 버튼을 둡니다. 회전과 같은 방식(되돌리기·취소 포함)으로 넣으면 됩니다.

## 2. 닉네임 꾸미기 (잠금 해제형)

- 이름표는 이미 캔버스가 아닌 HTML 요소라 색·테두리·작은 아이콘을 CSS로 바꾸기 쉽습니다. `NameTag`에 `setStyle(styleId)`를 두고, 스타일 목록은 코드 상수(색·테두리·배경)로 관리합니다. 사용자가 임의 색을 고르게 하지 않으면 가독성(최소 10px·대비)과 "말풍선과 구분" 원칙을 지킬 수 있습니다.
- **데이터**: `users.name_style`(짧은 문자열, 기본 `default`). 실시간 `room.state`/`member.join`에 이 값을 실어 다른 사람 화면에도 같은 이름표가 보이게 합니다(`Member.public()`).
- 내 캐릭터 구분(분홍)은 꾸미기와 별개로 유지하거나, 꾸민 이름표 옆에 작은 표시로 바꿉니다.

## 3. 특별 가구 잠금·보상

- **소유 테이블**: `user_unlocks(user_id, kind, key, unlocked_at)` 한 테이블로 가구 종류·가구 변형·이름표 스타일·테마를 모두 담을 수 있습니다(`kind`: `item`·`variant`·`name_style`·`theme`).
- **검사 위치**: 서버 `PUT /api/rooms/{id}/items` 검사에 "잠긴 종류·변형이면 거절"을 추가합니다. 이미 방에 놓인 것은 잠금 규칙이 바뀌어도 그대로 두는 편이 안전합니다(저장 때 새로 놓는 것만 검사).
- **보상 지급**은 서버만 합니다(클라이언트가 보낸 "획득"을 믿지 않음). 방명록·파티룸 참가·친구 수처럼 서버에 이미 기록이 있는 활동을 조건으로 쓰면 위조가 어렵습니다.
- 카탈로그에 `unlock` 조건을 적어 두면 화면(잠금 표시)과 서버(검사)가 같은 정의를 씁니다.

## 4. 테마별 방 구조

- 방 크기·창문·벽 장식·스폰은 이미 **템플릿**으로 분리되어 있습니다(파티 라운지가 첫 사례). 테마마다 구조를 바꾸려면 테마가 템플릿을 가리키게 하면 됩니다: `THEMES[id].template = 'personal-galaxy'`.
- 주의: 구조가 바뀌면 기존 가구가 새 방 밖으로 나갈 수 있습니다. 테마를 바꿀 때 서버가 `validate(layout, template)`로 먼저 검사하고, 맞지 않으면 테마 변경을 거절하거나 "가구 정리 후 변경" 안내를 띄웁니다. 지금처럼 크기가 같은 템플릿끼리는 문제없습니다.
- 카메라는 방 크기에서 자동으로 정해집니다(`core/camera.ts`). 개인룸보다 크면 `camera: 'follow'`로 따라가기를 켜면 됩니다.

## 5. 새 테마·추가 맵

- **테마 추가**: `themes.ts`에 색 세트를 더하고, DB CHECK(`rooms_theme_check`, `api/app/models.py` `THEMES`)를 넓히는 마이그레이션이 필요합니다. 가구·벽·바닥 그림은 테마 색을 받아 그리므로 새 그림은 필요 없습니다.
- **맵(방 종류) 추가**: `rooms.kind`에 값을 더하고(예: 상설 아지트 `hideout`), `furniture.json` `templates`에 새 템플릿을 둡니다. 권한은 `access.room_access`, 정원·수명은 파티룸 코드(`realtime/parties.py`, `Hub`의 `capacity`)를 참고해 종류별로 정합니다.
- 큰 맵은 파티 라운지처럼 따라가는 카메라와 말풍선 배치(`chat/bubbleLayout.ts`)를 그대로 씁니다.

## 지키면 좋은 원칙

- 카탈로그·규칙은 계속 `shared/furniture.json` 한 곳에 두고 프론트·서버가 같이 읽습니다(`shared/layout-cases.json` 같은 공통 사례로 양쪽 테스트).
- 새 열은 기본값이 있는 추가만 하고(기존 행 그대로), 운영 반영 전에 DB 사본에서 마이그레이션을 먼저 시험합니다.
- 픽셀아트는 캔버스, 글자는 HTML 층이라는 구분을 유지합니다(글자 선명도).
