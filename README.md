# 꾸미룸 (Ggumiroom)

나만의 작은 아이소메트릭 픽셀 방을 꾸미고, 캐릭터로 친구 방에 놀러 가는 웹 미니룸 서비스.
- **Phase 1** — 조작 가능한 아이소메트릭 미니룸 (이동·충돌·길찾기·깊이 정렬·테마)
- **Phase 2** — 현실 시간(Asia/Seoul)에 따라 창밖 풍경과 실내 분위기가 바뀌는 방
- **계정·친구 MVP** — 회원가입·로그인(서버 세션), 내 방(테마 저장), 닉네임 이름표, 친구 검색·요청·수락, 방 초대 링크 (FastAPI + PostgreSQL, `api/`)

## 실행

```bash
pnpm install
pnpm dev          # http://localhost:9020
pnpm typecheck    # TypeScript (strict) 검사
pnpm test         # 핵심 시스템 단위 테스트 (vitest)
pnpm build        # 프로덕션 빌드 → dist/
```

Node 24 / pnpm 12에서 확인했습니다.

### 조작

| 입력 | 동작 |
| --- | --- |
| 바닥 클릭 | 그 위치로 길을 찾아 이동 (가구·방 밖을 클릭하면 가장 가까운 빈 자리로) |
| ↑ ↓ ← → / W A S D | 화면 기준 방향으로 걷기. 두 키 조합(예: ↑+→)은 벽과 평행하게 이동 |
| 상단 테마 버튼 | 파스텔 / 갤럭시 / 플랜트 테마 전환 (캐릭터 위치·시간대 유지) |
| Enter | 채팅 입력창 열기 → 입력 후 Enter로 전송, Esc로 취소 (최대 24자, 말풍선 5초) |
| `dev · 시간대` 패널 (우하단) | 자동(KST) / 새벽 / 낮 / 노을 / 밤 강제 전환. **개발 모드(`pnpm dev`)에서만 표시, 운영 빌드에는 없음** |

키 입력은 진행 중인 클릭 이동을 즉시 취소합니다.

## 기술 스택

React 19 · TypeScript 7 (strict) · Vite 8 · Phaser 4 · Tailwind CSS 4 · pnpm

폰트: 오뮤 다예쁨체(omyu pretty) 하나로 페이지 UI와 게임 안 글자(이름표·말풍선)를 모두 씁니다. 라이선스상 폰트 파일은 **저장소에 포함하지 않습니다**. 제작사 원본 TTF를 수정 없이 `public/fonts/omyu-pretty.ttf`로 직접 넣어야 하며(Docker 빌드가 `deploy/fonts.sha256`으로 원본인지 확인), 없으면 시스템 글꼴로 표시됩니다 ([docs/DEPLOY.md](docs/DEPLOY.md#폰트-저장소에-포함하지-않음) 참고). 파일은 `index.css`의 `@font-face`로 불러오고, 손글씨체라 글자가 작게 보여 `size-adjust: 118%`로 키웠습니다. Phaser 글자는 처음 그릴 때 한 번 래스터화되므로 `main.tsx`에서 폰트 로드(최대 4초)를 기다린 뒤 앱을 시작합니다.

- **React**: 페이지 UI(헤더, 테마 전환, 방 이름, 조작 안내). 게임 프레임마다 리렌더링하지 않습니다.
- **Phaser**: 방 렌더링, 캐릭터 이동·애니메이션, 입력 처리.
- 백엔드·DB·인증·WebSocket 없음. 상태 관리 라이브러리 없음.

### 핵심 설계

**좌표계** — 모든 이동·충돌은 타일 단위 월드 좌표(`x`: 화면 우하향, `y`: 좌하향, 원점 = 방 안쪽 모서리)에서 처리하고, 렌더링 직전에만 `worldToScreen`(2:1 아이소메트릭, 타일 32×16px)으로 변환합니다. 스프라이트 위치는 정수 픽셀로 반올림해 확대 시에도 픽셀이 어긋나지 않습니다.

**이동** — 키보드와 클릭 모두 "원하는 월드 속도 → `CollisionWorld.move`" 한 경로를 거치므로 속도·충돌·미끄러짐이 동일합니다. 속도는 초당 타일(2.6)로 프레임 독립적이며, 긴 프레임은 100ms로 제한합니다.

**충돌** — 캐릭터는 반지름 0.22 타일의 원, 가구는 바닥 점유 사각형입니다. 이동을 반지름 절반 이하의 하위 단계로 나눠 터널링을 막고, 겹치면 접촉 법선 방향으로 밀어내 벽면과 모서리를 따라 자연스럽게 미끄러집니다.

**길찾기** — 캐릭터 크기만큼 장애물을 부풀린 0.25 타일 격자에서 8방향 A*(모서리 가로지르기 금지)를 돌리고, 시야 검사로 불필요한 꺾임을 제거합니다. 막힌 곳을 클릭하면 가장 가까운 도달 가능한 빈 자리로 갑니다.

**깊이 정렬** — 단일 정렬 키(`x + y`)는 침대처럼 긴 가구에서 틀리므로, 화면상 겹치는 쌍만 "누가 뒤인가" 관계를 만들어 위상 정렬합니다. 바닥 → 벽 → 바닥 장식(러그·방석) → [가구·캐릭터 정렬 레이어] 순입니다.

**캐릭터** — 방향(`front/back × left/right`, 좌측은 좌우 반전)과 애니메이션 상태(`idle/walk`)를 분리해 관리합니다. 정면 대기 중에는 가끔 눈을 깜빡입니다.

**카메라** — 고정 카메라가 방 전체가 들어오는 최대 **정수 배율**로 확대합니다(픽셀 선명도 유지). 화면이 아주 작으면 소수 배율로 축소합니다.

**WebGL 미지원** — `Phaser.AUTO`로 WebGL을 우선 사용하고, 불가하면 Canvas 렌더러로 자동 전환되며 UI에 안내가 표시됩니다(Phaser 4에서 Canvas 렌더러는 deprecated지만 동작함을 확인).

## 시간대 시스템 (Phase 2)

| 시간대 | 시각 (KST) | 창밖 | 실내 |
| --- | --- | --- | --- |
| 새벽 | 06:00–06:59 | 연보라·연분홍 하늘, 아래쪽에 떠오르는 해의 테두리, 구름 1개, 희미한 별 2개 | 은은한 라벤더, 스탠드 약하게 |
| 낮 | 07:00–17:59 | 맑은 하늘, 창 오른쪽 위에 걸친 해, 천천히 흐르는 구름 2개 | 밝고 따뜻하게 (거의 그대로) |
| 노을 | 18:00–19:59 | 보라→분홍→주황 하늘, 창 아래에 걸린 해, 노을빛 구름 | 따뜻한 노을빛, 스탠드 반쯤 |
| 밤 | 20:00–05:59 | 남색·보라 하늘, 창 왼쪽 위에 걸친 초승달, 제각각 반짝이는 별 | 약 80% 밝기, 스탠드 주변 따뜻한 빛 |

**시간 판단** — `Intl.DateTimeFormat`으로 Asia/Seoul 시각을 구하므로 기기 시간대와 무관합니다. 자동 모드는 다음 경계 시각까지 `setTimeout` 하나로 기다리고(폴링 없음), 탭이 다시 보이면(`visibilitychange`) 시각을 재확인합니다. 백그라운드 탭의 타이머 지연이나 노트북 절전도 이 경로로 보정됩니다.

**창문 구조** — 창틀·창살·커튼(정적, 테마별 텍스처)과 창밖 풍경(동적)을 분리했습니다. 창문 위치·크기는 `RoomData.windows`(`wall`, `u0..u1`, `z0..z1`)로 지정하며, 왼쪽·오른쪽 벽 모두 지원합니다.

**마스킹 방식과 이유** — Phaser 4의 마스크는 WebGL 필터라서 Canvas 렌더러 폴백과 동작이 다릅니다. 대신 창밖 풍경을 작은 CanvasTexture(약 22×45px)에 직접 합성하면서 **유리 영역(벽면 위 평행사변형) 밖의 픽셀을 버립니다**. 그래서 두 렌더러에서 결과가 같고 경계가 픽셀 단위로 정확하며, 구름·별·해·달이 창틀 밖으로 나갈 수 없습니다. 하늘은 먼 풍경이라 기울이지 않고 화면 기준으로 그리며, 잘라내는 모양만 벽면을 따릅니다.

**애니메이션** — 구름은 초당 0.3–0.5px로 흐릅니다. 창 밖으로 완전히 나간 뒤 여유 간격을 두고 반대편에서 들어오므로 되돌아가는 순간이 보이지 않습니다. 별은 각자 다른 주기·위상의 두 사인파로 밝기 4단계를 오갑니다. 풍경은 10Hz로 확인하되 **보이는 픽셀이 바뀔 때만** 다시 그립니다(실측 초당 0.4–0.8회).

**조명** — MULTIPLY 사각형 하나로 실내 전체 색을 바꾸고(밤에도 약 80% 밝기 유지), 실내 광원은 실제 면 위에 빛을 놓습니다. 스탠드는 전등갓의 작은 후광, 뒤쪽 벽면의 타원 빛, 바닥 빛(가구 아래 층이라 협탁이 자기 밑 부분을 가림)으로, 모니터는 화면 면과 그 앞 책상 윗면의 부채꼴 빛으로 그립니다(바닥 빛 없음). 화면 기준 원을 가구 위에 덮지 않으므로 공간과 어긋나지 않습니다(`art/lampArt.ts`). 모두 표시 전용이라 충돌·깊이 정렬에 영향이 없고, 시간대가 바뀌면 1.2초 동안 부드럽게 전환됩니다.

**창문 자연광** — 스탠드 조명과 별개인 `WindowLight`가 관리합니다. 창문은 광원이 아니라 빛이 들어오는 통로로 보이도록, 유리 광택과 창 주변 후광은 아주 약하게(실내 조명 MULTIPLY 아래 층) 두고, 빛의 존재감은 바닥 패턴이 맡습니다. 바닥 빛은 화면에 사각형을 그리는 대신, 바닥 픽셀마다 월드 좌표로 바꾼 뒤 투영 모델(`SunRay`: `start` 유리 아래쪽이 닿는 벽과의 거리, `reach` 방 안쪽으로 늘어나는 길이, `slant` 벽을 따라 비껴가는 기울기, `spread` 안쪽으로 갈수록 넓어지는 정도)로 유리까지 역추적해 유리에 닿을 때만 칠합니다. 그래서 창문 위치·크기를 따라 바닥에 눕고, 창살 4칸이 길쭉하고 비스듬한 사다리꼴로 나타납니다. 창문 바로 아래 벽·바닥 경계에서 패턴까지는 옅은 리드인 빛이 이어집니다. 창문과 바닥 사이 공중에는 유리 각 점에서 바닥 착지점까지 광선을 따라 찍어 만든 옅은 빛 영역(`drawLightShaft`)이 있어, 창문 → 공중 → 바닥이 하나의 흐름으로 보입니다. 이 공중 빛은 램프 후광처럼 가구·캐릭터 위, 실내 조명 아래 층에 그립니다. 빛 단계는 몇 개로 고정(코어 / 창살 그림자 / 가장자리 체커보드)해 픽셀아트답게 유지합니다. 바닥 빛은 러그 위·가구와 캐릭터 아래 층(ADD)이라 그 위에 덮이지 않습니다. 시간대별 텍스처는 처음 한 번만 만들어 캐시하고, 전환 시 1.2초 크로스페이드하며 매 프레임 다시 그리지 않습니다. 창문빛의 색·세기는 노을과 새벽의 중간값 하나로 모든 시간대에 똑같이 쓰고, 바닥에 떨어지는 위치·방향만 해를 따라 바뀝니다(새벽 왼쪽으로 길게, 낮 짧고 곧게, 노을 오른쪽으로 길게, 밤 달빛 왼쪽으로 짧게). 책상 모니터는 바닥 빛 없이 화면 주변만 차가운 색으로 빛나고, 밤에 가장 밝고 낮에는 거의 보이지 않습니다.

**테마 연동** — 세 테마가 같은 시스템을 씁니다. 테마는 `RoomTheme.env`에서 시간대별로 일부 값만 덮어씁니다. 예: 갤럭시룸은 원래 어두우므로 밤에 덜 어두워지고 별이 노란색으로 더 많이 뜹니다. 플랜트룸은 낮과 노을이 더 따뜻합니다.

**성능·접근성**
- React는 시간대가 바뀔 때만 배지를 갱신합니다.
- 숨겨진 탭에서는 브라우저가 rAF를 멈추고, 추가로 `document.hidden`이면 풍경 갱신을 건너뜁니다.
- `prefers-reduced-motion: reduce` 환경에서는 구름과 별이 멈춘 상태로 그려지고 조명이 즉시 바뀝니다.
- 텍스처는 키별로 캐시되며, 테마를 바꿀 때 풍경 텍스처를 재사용합니다.

## 아트 에셋

레퍼런스 이미지는 콘셉트 아트로만 참고했고, 게임에 잘라 쓰지 않았습니다. 이미지 생성 도구가 없어 **모든 그래픽은 코드로 생성한 임시 픽셀아트**입니다.

- 가구·벽·바닥: 픽셀 단위 아이소메트릭 박스 래스터라이저(`art/pixelCanvas.ts`)로 그림 (안티앨리어싱 없음)
- 캐릭터: 팔레트 문자열로 직접 찍은 16×25 스프라이트 시트 (`art/avatarArt.ts`)
- 바닥·벽·가구·캐릭터는 모두 독립된 텍스처/게임 오브젝트입니다.

### 실제 에셋으로 교체하는 법

생성기는 같은 키의 텍스처가 이미 있으면 건너뜁니다. Preloader 씬에서 아래 키로 PNG를 로드하면 됩니다.

| 대상 | 텍스처 키 | 규격 |
| --- | --- | --- |
| 가구 | `furniture:<id>:<theme>` | 폭 `(w+h)*16+2`, 높이 `(w+h)*8+height+2`. 가구 뒤쪽 모서리 바닥점 = 픽셀 `(h*16+1, height+1)` (`spriteFrame()` 참고) |
| 캐릭터 | `avatar:default` | 16×25 프레임 7개, 프레임 이름 `front-idle/front-blink/front-stepA/front-stepB/back-idle/back-stepA/back-stepB`, 발 기준점 (8, 24) |
| 바닥/벽 | `floor:<theme>:<w>x<h>`, `walls:<theme>:<w>x<h>` | 기준점은 `art/roomArt.ts` 참고 |

## 미완성 / 알려진 제약

- 아트는 전부 임시입니다. 테마는 색상만 바뀌고 가구 구성은 세 테마가 같습니다(갤럭시 별빛·플랜트 식물 등 테마 고유 소품 없음).
- 정수 배율만 쓰므로 중간 크기 화면(예: 높이 ~600px)에서는 방이 다소 작게 보입니다. 모바일 대응 시 배율 정책을 다시 정해야 합니다.
- 가구 회전, 벽걸이 가구의 독립 오브젝트화(지금은 창문·액자·선반이 벽 텍스처에 포함), 캐릭터 8방향 스프라이트 없음.
- 침대 뒤 공간처럼 캐릭터가 들어갈 수 없는 좁은 틈은 그대로 둡니다(의도된 동작).
- 이름표는 Phaser Text라 시스템 폰트에 의존합니다.
- 실내 조명은 화면 전체에 MULTIPLY를 적용하므로, 밤에는 방 주변 배경까지 함께 어두워집니다(의도된 분위기). 이름표는 조명 위 레이어라 어두워지지 않습니다.
- 시간대 전환은 경계에서 1.2초 동안 페이드됩니다. 시간대 안에서 하늘이 점점 밝아지는 연속 변화는 없습니다.
- 일출·일몰 API, 날씨, 계절 변화는 범위 밖이라 구현하지 않았습니다.

## 다음 단계 제안

`Avatar`는 입력과 분리돼 있어 원격 플레이어를 같은 클래스로 그릴 수 있고, `RoomData`는 직렬화 가능한 형태라 저장·공유·소셜룸에 그대로 쓸 수 있습니다. 이후 순서 제안:

1. 실제 픽셀아트 에셋 제작 및 Preloader 씬 추가
2. 가구 배치 에디터 (격자 스냅, 충돌 검사는 `CollisionWorld` 재사용)
3. 방 데이터 저장(백엔드) → 친구 방 방문
4. WebSocket 멀티플레이어(소셜룸) — 원격 `Avatar`를 위치 보간으로 구동
5. 채팅 말풍선, 방명록, BGM

## 채팅 (로컬 말풍선)

DB·WebSocket 없이 브라우저 안에서만 동작합니다. 새로고침하면 사라지고 아무 데도 저장하지 않습니다.

- **흐름**: `ChatBar`(React) → `GameHandle.sendChat` → `normalizeChat`(공백 정리, 빈 메시지 거부, 24자 제한) → `ChatTransport.send` → `onMessage` → `RoomScene.showChat` → `SpeechBubble`.
- **전송과 표시 분리**: 말풍선은 `ChatMessage`만 받습니다. 지금은 `LocalChatTransport`가 보낸 메시지를 그대로 되돌려 주고, 나중에 `createGame.ts`에서 `WebSocketChatTransport`로 바꾸면 다른 플레이어의 메시지도 같은 경로로 들어옵니다. 서버는 클라이언트가 보낸 `playerId`·`createdAt`을 믿지 말고 인증 정보와 서버 시각으로 다시 채워야 합니다.
- **입력**: 입력창에 포커스가 있는 동안 Phaser 키보드 매니저를 꺼서 W/A/S/D·방향키가 캐릭터를 움직이지 않고 글자로 입력됩니다. 한글 조합 중 Enter(`isComposing`/keyCode 229)는 전송하지 않고, 전송 직후 들어오는 중복 Enter로 입력창이 다시 열리지 않게 막습니다.
- **말풍선**: 실제 폰트 너비로 줄바꿈해 최대 2줄, 크기는 렌더링된 글자에 맞춥니다. 이름표 위, 모든 가구·조명 위 UI 층에 그리고, 매 프레임 캐릭터를 따라가며 카메라 화면 밖으로 나가지 않게 보정합니다(꼬리는 캐릭터를 계속 가리킴). 새 메시지는 이전 말풍선과 타이머를 즉시 교체하고, 테마를 바꿔도 남은 시간 그대로 유지됩니다.

## 계정 · 친구 · 초대 (MVP)

백엔드는 `api/`(FastAPI + PostgreSQL)이고, 실행·스테이징·운영 반영·백업은 [docs/DEPLOY.md](docs/DEPLOY.md#백엔드-fastapi--postgresql)에 있습니다.

| 화면 | 내용 |
|---|---|
| `/` | 로그인 전: 기존 데모 방 그대로(이름표 '꾸미'). 로그인 후: 내 방(이름표 = 내 닉네임, 테마 저장) |
| `/signup`, `/login` | 닉네임·아이디·비밀번호·확인 4칸 / 아이디·비밀번호. `?next=`는 앱 안 경로만 허용 |
| `/room/{id}` | 친구 방 또는 초대받은 방. 혼자 둘러보기만 가능하고, 실시간 함께 놀기는 미구현이라고 안내 |
| `/invite/{token}` | 로그인 없이 보이는 초대장. 가입·로그인 후 그 방으로 이동 (초대 맥락은 sessionStorage에 보관) |
| 방 안 `👥 친구` | 친구 목록(놀러 가기·삭제), 받은/보낸 요청(수락·거절·취소), 닉네임 검색 |
| 방 안 `💌 친구 초대하기` | 초대 링크를 클립보드에 복사 (7일 유효, 같은 링크 재사용) |

- 인증: HttpOnly·Secure·SameSite=Lax 세션 쿠키(서버 DB에 토큰 해시만 저장, 30일, 로그아웃 시 삭제) + CSRF 이중 제출 토큰 + Origin 검사. 브라우저 저장소에 인증 토큰 없음.
- 비밀번호: Argon2id, 8~128자, 흔한 비밀번호·아이디 포함 금지. 이메일을 받지 않아 분실 시 복구 불가(가입 화면에 안내).
- 초대 링크로 들어와도 친구가 되지는 않습니다(방 방문 권한만 생김).

## 방 꾸미기 (가구 배치)

내 방 좌측 패널의 **🛋 방 꾸미기**로 들어갑니다. 저장하기 전까지는 편집 상태에만 반영되고, 취소하면 원래 배치로 돌아갑니다.

| 동작 | 데스크톱 | 태블릿·모바일 |
|---|---|---|
| 고르기 | 가구 클릭 (화면에서 앞에 보이는 가구가 우선) | 탭 |
| 옮기기 | 끌기, 방향키 한 칸 | 끌기, 하단 도구의 ↖↗↙↘ |
| 돌리기 / 빼기 | 오른쪽 클릭 / 휠 버튼 클릭, R / Delete (패널 버튼도 있음) | ⟳ 돌리기 / 🗑 빼기 |
| 추가 | 패널의 가구 목록 | ＋ 가구 (바텀시트) |
| 패널 | 꾸미는 동안 좌측 패널은 펼친 채 고정(접기 버튼 숨김), 끝나면 원래 접힘 상태로 | 게임 아래 도구 막대 |
| 되돌리기 | Ctrl+Z / ↶ | ↶ |

- **마우스 단축 조작은 꾸미기 중에만**: 오른쪽 클릭은 선택한 가구를 돌리고(선택이 없으면 포인터 아래 가구), 브라우저 메뉴는 뜨지 않습니다. 휠 버튼 클릭은 빼기이고 자동 스크롤이 시작되지 않습니다. 휠 스크롤은 아무것도 바꾸지 않습니다. 게임 화면 밖 클릭이나 화면 밖에서 뗀 클릭은 배치에 영향이 없고, 꾸미기 밖에서는 평소처럼 동작합니다. 돌리기·빼기는 모두 되돌리기(Ctrl+Z)와 취소에 포함됩니다.
- **카탈로그와 규칙은 한 파일**: `shared/furniture.json`(가구 크기·막힘 여부·기본 배치·방 크기·최대 40개)을 프론트(`src/game/core/placement.ts`)와 API(`api/app/layout.py`)가 함께 읽고, `shared/layout-cases.json`의 같은 사례로 양쪽을 테스트합니다.
- **규칙**: 0.25칸 격자, 방 안, 막힌 가구끼리 겹치지 않기(러그·방석 위는 가능), 캐릭터 자리 피하기, 바닥을 막아 1칸(16셀) 이상 갈 수 없는 구역을 만들지 않기(구석의 아주 작은 빈틈은 허용), 최대 40개. 편집기는 규칙을 어기는 변경을 적용하지 않고 이유를 알려 주며(놓은 자리가 안 되면 제자리로), 서버도 저장할 때 같은 규칙으로 다시 검사합니다(422).
- **회전 2방향**: 방향 1은 같은 가구를 90도 돌린 것으로, 그림 생성기가 월드 x·y를 바꿔 다시 그립니다(좌우 반전이 아님). 그래서 밝은 면·어두운 면이 광원 방향 그대로입니다.
- **저장**: `PUT /api/rooms/{id}/items`로 전체 배치를 한 번에 교체합니다. `layout_version`이 다르면(다른 창·기기에서 먼저 저장) 409를 돌려주고, 화면은 "최신 배치 불러오기"를 안내합니다.
- **빼기**는 그 방에서만 빠지는 것이고 가구를 잃지 않습니다. 모든 가구는 무료 카탈로그에서 언제든 다시 추가할 수 있습니다.
- 저장 후 게임이 방을 다시 구성해 충돌·길찾기·스탠드/모니터 빛 위치가 새 배치를 따르고, 캐릭터가 가구 안에 있게 되면 가장 가까운 빈자리로 옮겨집니다. 편집 중에도 빛은 가구를 따라 움직입니다.
- 창문 위치, 벽 소품(액자·선반·가랜드)은 이번 단계에서 고정입니다.
